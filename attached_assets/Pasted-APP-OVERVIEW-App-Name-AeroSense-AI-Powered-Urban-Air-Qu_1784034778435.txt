APP OVERVIEW
App Name: AeroSense — AI-Powered Urban Air Quality Intelligence Platform
One-line description: A multi-agent AI platform that fuses CAAQMS station data, satellite/mobility signals, and geospatial land-use layers to attribute pollution sources, forecast hyperlocal AQI 24-72 hours ahead, and generate prioritized enforcement + citizen health advisories for Indian cities.
Core problem it solves: India has 900+ air quality monitoring stations generating data, but only 31% of cities convert that data into actionable, multi-agency response protocols. AeroSense closes the "signal-to-intervention" gap by adding a geospatial attribution engine, a hyperlocal forecasting model, and an enforcement prioritization agent on top of raw monitoring data — turning dashboards into decisions.
Target user: City pollution control administrators, municipal enforcement officers, and citizens (via a public-facing health advisory view) in Tier 1/Tier 2 Indian cities.

FULL FEATURE LIST
Core (must-have, judge-facing)

Live City AQI Map — Leaflet.js map with color-coded ward/zone markers showing real-time AQI (from CPCB/OpenAQ API or seeded mock data).
Geospatial Source Attribution Engine — For any selected ward, an AI agent (LLM-based reasoning over structured inputs: land use, traffic density, industrial stack proximity, construction permits) outputs a ranked breakdown of pollution sources (e.g., "62% vehicular, 24% construction dust, 14% industrial") with a confidence score.
Hyperlocal 24–72hr AQI Forecast — Time-series forecast (LSTM or a lightweight statistical model, e.g., Prophet/ARIMA if time-constrained) per ward, displayed as a forecast chart with confidence bands, benchmarked against a persistence baseline.
Enforcement Intelligence Dashboard — Ranks pollution hotspots against registered emission sources and outputs a prioritized action list ("Deploy inspector to Zone 4 industrial cluster — highest violation probability") with supporting evidence (map snippet + data points).
Citizen Health Risk Advisory (bilingual Tamil/English) — Ward-level advisory cards (e.g., "Poor air quality expected in Adyar by 6PM — outdoor workers and elderly should limit exposure") generated via LLM, toggleable between Tamil and English.
RAG-powered "Ask AeroSense" Chat — Chatbot (ChromaDB + Groq LLaMA or similar) answering natural-language questions like "Why is AQI high in T Nagar today?" using retrieved context from live + historical data.
Multi-Ward Comparative View — Side-by-side comparison of 3–5 wards/zones showing AQI trend lines and effectiveness of past interventions (mock data acceptable).

Nice-to-have (polish/differentiation)

Animated AQI trend sparklines on each ward marker popup.
"What-if" simulator slider (e.g., "reduce construction activity by 30%" → recalculated forecast).
IVR/SMS advisory mock (a UI panel simulating an SMS push, no real telephony needed).
Downloadable PDF enforcement report per zone.
Dark/light mode toggle.


TECH STACK

Frontend: React (Vite) + TailwindCSS + shadcn/ui components + Leaflet.js (via react-leaflet) for maps + Recharts for forecast/trend charts
Backend: FastAPI (Python)
Database: PostgreSQL (via Replit's built-in Postgres or SQLite fallback for speed) — use SQLAlchemy ORM
Caching/Session (optional, skip if time-constrained): Redis — otherwise in-memory caching
AI/LLM Layer: Groq API (Llama 3.3 70B) for source attribution reasoning, advisory generation, and the RAG chatbot
Vector Store (RAG): ChromaDB (embedded, local persistence) for storing historical AQI reports/context for retrieval
Forecasting Model: Lightweight — either a pre-trained/mock LSTM (PyTorch) if time allows, OR a simple moving-average + seasonal adjustment model in Python (statsmodels) to guarantee it works live in a demo
Maps: Leaflet.js + OpenStreetMap tiles (free, no API key needed)
Deployment: Replit's built-in run/deploy (single Repl, FastAPI serving both API + static React build, or two-service Repl)


PAGES & USER FLOW

Landing / Login-less Home → City selector (default: Chennai) → routes to Dashboard.
Dashboard (Map View) — Main page. Leaflet map of city wards color-coded by current AQI. Sidebar shows city-wide AQI summary stat cards (current AQI, trend arrow, top pollutant). Clicking a ward marker opens a side panel.
Ward Detail Panel (slide-over, not full page) — Shows: current AQI, Source Attribution breakdown (pie/bar chart + confidence %), 72hr forecast chart, and a "Generate Advisory" button.
Enforcement Intelligence Page — Table/list of prioritized enforcement recommendations across all wards, sortable by priority score, each row expandable to show evidence.
Citizen Advisory Page — Public-facing simplified view: pick your ward → see plain-language health advisory in Tamil or English, with icons for vulnerable groups (elderly, outdoor workers, schools).
Compare Zones Page — Multi-select 2–5 wards → overlay trend charts + intervention effectiveness table.
Ask AeroSense (Chat) — Persistent floating chat widget accessible from all pages; full-page chat view also available.

Navigation: Top navbar with tabs — Dashboard | Enforcement | Advisories | Compare | Ask AeroSense — plus a city selector dropdown (Chennai, Mumbai, Delhi, Bengaluru, Kolkata as mock options).

UI & DESIGN INSTRUCTIONS

Color scheme: Deep slate/navy base (#0F172A) for dark mode dashboard feel, with AQI severity colors as accents: Good=#22C55E, Moderate=#EAB308, Poor=#F97316, Severe=#EF4444, Hazardous=#7C1D6F. Primary accent: teal/cyan (#06B6D4) for CTAs and highlights.
Fonts: Inter or Manrope for UI text; monospace (e.g., JetBrains Mono) for AQI numeric readouts to give a "data intelligence" feel.
Layout style: Dashboard-first, card-based, generous spacing, sidebar + main content split on desktop, collapsible on mobile. Use subtle glassmorphism (translucent panels with blur) over the map for the ward detail slide-over.
Components: shadcn/ui cards, badges (for AQI severity), tabs, sliders (what-if simulator), toast notifications for advisory pushes.
Animations: Framer Motion for panel slide-ins, number count-up animation for AQI stat cards, subtle pulse animation on hazardous-zone map markers.
Must look polished: consistent spacing scale (4/8/16/24px), skeleton loaders while data fetches, empty states with icons, no browser-default form elements.


DATA & APIS
Data Models (SQLAlchemy / Postgres schema)
Ward
- id, name, city, lat, lng, population, land_use_type

AQIReading
- id, ward_id (FK), timestamp, aqi_value, pm25, pm10, no2, so2, co, source (station/mock)

SourceAttribution
- id, ward_id (FK), timestamp, source_category, contribution_pct, confidence_score

ForecastRecord
- id, ward_id (FK), forecast_timestamp, predicted_aqi, confidence_lower, confidence_upper

EnforcementAction
- id, ward_id (FK), priority_score, source_type, recommendation_text, evidence_json, status

Advisory
- id, ward_id (FK), language (ta/en), risk_level, message_text, generated_at
APIs to integrate

OpenAQ API (free, no key for basic tier) — https://api.openaq.org/v3/locations?country=IN and https://api.openaq.org/v3/measurements for real Indian AQI station data as a seed/fallback.
Open-Meteo API (free, no key) — https://api.open-meteo.com/v1/forecast?latitude={lat}&longitude={lng}&hourly=temperature_2m,windspeed_10m,winddirection_10m for meteorological inputs used in forecast reasoning.
Groq API — https://api.groq.com/openai/v1/chat/completions with llama-3.3-70b-versatile for: source attribution reasoning, advisory text generation, and RAG chat responses.
OpenStreetMap tile server (free) — https://{s}.tile.openstreetmap.org/{z}/{x}/{y}.png for Leaflet base map.

Mock/seed data

Seed 8–10 wards for Chennai (e.g., T Nagar, Adyar, Anna Nagar, Velachery, Guindy, Mylapore, Perambur, Tambaram) with realistic lat/lng.
Generate 30 days of synthetic hourly AQI readings per ward (randomized with realistic diurnal + seasonal patterns) via a Python seed script if OpenAQ data is sparse for Chennai.
Pre-populate 3–5 sample enforcement recommendations and advisories so the UI never looks empty on first load.

Build FastAPI endpoints:

GET /api/wards — list all wards with latest AQI
GET /api/wards/{id}/readings?range=24h — historical readings
GET /api/wards/{id}/attribution — calls Groq LLM with ward's land-use/traffic/industrial context to generate source attribution JSON, cache result for 1 hour
GET /api/wards/{id}/forecast — runs the forecasting model (statsmodels or simple moving average + seasonal factor) and returns 72hr predicted values with confidence bands
GET /api/enforcement — returns prioritized list combining hotspot + source data
GET /api/advisories/{ward_id}?lang=ta|en — calls Groq to generate bilingual advisory text
POST /api/chat — RAG endpoint: embed query, retrieve from ChromaDB (seeded with ward summaries + historical reports), send context + query to Groq, return answer
